# hirdir 0.9.13

For the daily work of an Admin and of an operator, with fewer clicks: a new person is
made as a user, a contact and an operator by one form, the lists of users, contacts
and operators each say which of the others a person is and find those that are not, a
colour is pressed and no longer typed, and every table is taken out from the page that
loads it, an empty one as the template of its import, and loads back as nothing to
change.

## New

- **A new person in one step** (P-283). Admin, Users, New user is one form with one
  Create: the user, the contact it is and the operator it works as, with the role, the
  groups and the notes. Also a contact and Also an operator are ticked from the start;
  the operator's label follows the username until it is typed over, and its colour is
  the next that no operator has. A refusal is shown at its field with nothing typed
  lost, and where any part is refused nothing is made. Until now it took the Users
  page, the Groups page twice and the Operators page: 25 clicks, 92 keys and six
  pages for an engineer in two groups, where it is now 9 clicks, 53 keys and one.
  `POST /users` takes `operator`, `group_hids` and `notes`, and makes all of it in one
  change, each record audited as if it were made by itself.
- **Who is a user, a contact and an operator, on each list** (P-280). The Users list
  shows the contact and the operators of each user, the Contacts list the user and the
  operators of each contact, the Operators list the user behind each operator: each a
  link to the other record, and plain words where there is none. Show, above each
  list, narrows it to its gaps in one press: users with no contact, users with no
  operator, contacts that are no user, contacts behind no operator, operators with no
  user behind them and with nobody behind them. A user whose contact is retired is
  among those with no contact and no operator, so that what is left of somebody who
  left is found.
- **A user's groups, from the user's own page** (P-282): a box to each group there is,
  with what the group grants; ticking and unticking add and remove the user at once.
- **Notes on a user** (P-281): what the account is for, who asked for it, when it is
  to end. They are an Admin's to write and to read, on the Users list and the user's
  page; a person's own sign-in does not give them.
- **Make an operator, in one press** (P-284), on the page of a user and of a contact
  who is behind none: the label is the username, or the contact's name, and the colour
  the next unused.
- **A colour is pressed** (P-285). Wherever a colour is entered, an operator's and a
  tag's, there is a grid of 64, eight hues in eight shades, a slider of 32 that moves
  the choice in the grid, and the box that still takes any `#rrggbb`. The three are one
  value. It is shown on a chip filled with the colour, its text black or white,
  whichever reads better, beside the label as the lists will show it. All of it is
  worked by the keyboard. `GET /colours` gives the grid, the slider and the next
  colour for an operator.
- **Every table exported from the Import page** (P-286). Beside the upload, every
  table a file is taken for, in the order of loading, with how many records it holds
  and CSV and JSON, one press each: the whole table in the form that loads back. A
  table that holds nothing gives the header row of its file, the template of its
  import. Export everything saves one zip of every table, as CSV or as JSON; that the
  whole inventory was taken out, by whom and when, is in the audit trail. Twenty
  shipping addresses of sites corrected in a spreadsheet are six clicks, the file out
  and back, where there was no way but one site at a time.
- **What is exported loads back** (P-286). The file of any table, loaded into the
  inventory it came from, changes nothing: every row unchanged, none rejected, in both
  formats. A test holds it for all 33 tables, and the package test holds it on a fresh
  installation and on one upgraded from 0.9.12.
- **Geography exported as its three tables** (P-287), regions, sites and locations,
  each as CSV and as JSON, from the Geography page.
- **The users as CSV** (P-288), for an Admin, from Admin, Users: a row to each user
  with its person, role, groups, operators, kind, state, last sign-in and notes. It
  holds no access code, no token and no hash of either, and it is audited. No file
  makes or changes a user.
- **`hirdir export --all`** writes the zip of every table from the command line.

## Changed

- **An operator's page reads Details first**, above The person's email and numbers,
  and the New operator form fills the label with the username of the person chosen
  (P-284).
- **The Users list is whole in view at 1280 pixels**, its notes among its columns:
  the email stands beneath the name, and the two numbers in one cell.
- **The Users list reads its page in the same few statements whatever its size**; it
  asked twice more for every row. So for the list of user groups.
- **The name of a user group holds no semicolon**, which separates the groups of a
  user in the users' file. A group that has one keeps its name until it is renamed.
- **`POST /exports` takes `whole`**, the whole table in the form that loads back, as
  the zip holds it.

## Fixes

- **A text that is exactly `!clear` loads back.** A note or a description that held
  the mark an import clears a value by was written bare by an export, and loading that
  file back erased it. It is written guarded now, and read back as it was.

## Additional Notes

- **Upgrade.** Migration `0016` adds the notes of a user, blank, and changes no
  record. See [From 0.9.12 to 0.9.13](../install.md#from-0912-to-0913).
- **The zip of every table is for the inventory it came from.** Its rows carry the
  IDs of their records, which an empty inventory does not hold: an inventory is moved
  to another server by a backup and a restore, as before.
- **A user that is disabled stays in the gaps** of the Users list, and a colour sent
  blank makes an operator with no colour: only a colour left out is chosen by the
  server. The New user form sends the colour it shows.
- **Export everything takes about a minute at 50,000 items**, nearly all of it the
  items, and goes out as it is written; the list of tables with its counts takes a
  few milliseconds.
- **Next, 0.9.14**, the round of the person: a profile page of one's own (P-289), the
  user, the contact and the operators of one person retired together (P-291), and a
  user account that is retired, other than disabled (P-292). After 1.0.0: the words
  the pages show gone over for plain writing (P-290), and formats for what is typed or
  pasted (P-293).
