# hirdir 0.9.16

One option of a command, and a quicker way to release. `hirdir admin create-user` puts
the new user in groups, so that a person whose role comes from a group is made with it;
and a release is tested by what it changes, in two tiers, with the package built once.

## New

- **`hirdir admin create-user --group NAME`** (P-304), given once for each group, by its
  name in any case. A group that grants a role gives the user that role, as it does on
  New user, so a person made with such a group and no `--role` signs in, and the command
  says which role it holds through its groups; it warns that the account holds no role
  only where it holds none. A name that no group has is refused, with exit `4`, before
  anything is made. Each membership is audited as one made on the page is.

## Changed

- **What a release is tested by** (P-305, amending D-76). A small change, such as this
  one, is tested by `make check`, `make acceptance`, the browser scenarios on the host
  that it reaches, one build of the package, and the package test's upgrade from the
  release before and its fresh install, in about 50 minutes; an ordinary release adds
  the browser scenarios of every spec file changed since the release before, the failed
  upgrade, and a short check through nginx, in about an hour. Every browser scenario is
  run again against the installed package only for a change to the packaging, nginx,
  the prefix or the frame of the page, and for 1.0.0. The release notes are written
  before the package is built, and it is built once. See
  [Release process](../release-process.md#steps).

## Additional Notes

- **Upgrade.** No migration: the schema stays at revision `0017`, and nothing that is
  held is changed. See [From 0.9.15 to 0.9.16](../install.md#from-0915-to-0916).
- **This release's test**: `make check`, `make acceptance`, one `make deb`, then the
  package test's `--upgrade` from 0.9.15 and `--fresh`; no browser scenario, since no
  page changed.
- **Next, 1.0.0**: no new feature. Timing at 50,000 items, the upgrade test from every
  earlier release, accessibility, and the documentation complete. After it: the words
  the pages show gone over for plain writing (P-290), and formats for what is typed or
  pasted (P-293).
