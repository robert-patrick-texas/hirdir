# hirdir 0.4.2

The answers to what the review of 0.4.1 found unsaid. One of them changes how a time is
read, which is why this release follows so soon.

## Changed

- **A time that names no zone is in the application's time zone.** A moment that is
  observed, of an item, of a group or of the master that is seen of a stack, given in
  a request or in a file as `2026-11-02T10:00:00`, is ten in the morning in the
  `time_zone` setting, which is America/New_York until it is changed. It is typed as
  it is read on a page. 0.4.1 read it as UTC. A moment that names its zone, or ends in
  `Z`, is that moment, as before.
- **A filter reads a time the same way.** `observed_at:gte:2026-11-02T10:00` compares
  with ten in the morning in the application's time zone, so what was entered is found
  as it was entered. It holds for every time a list filters by. A script that means
  UTC adds `Z`.
- **The item grid shows no money until it is asked for.** Estimated value is in the
  column chooser, beside Annual support cost and Support weight, and filters, sorts and
  exports as before. A layout that a person has saved is as they saved it.
- **A health that is not known says what is there.** For an item with a condition that
  a site added to the list, the reason reads "its condition is in-repair, which says
  nothing of its health, and nothing is observed", and for an untested one, "its
  condition is untested, and nothing is observed". It read "nothing is said of its
  condition", which was not so. The health itself is as it was.
- **The examples' licence is one licence.** NetConfig Manager had quantity 250, which
  multiplied its annual support cost into nearly all of the examples' total. It has
  quantity 1 and says in its description that it is for 250 devices.

## Additional Notes

- Every component is at its latest production release. Nothing is held back.
- Upgrading from 0.4.1 changes nothing that is held: there is no migration, and the
  schema stays at revision `0006`. A moment that 0.4.1 stored from a value with no zone
  stays the moment it was given, in UTC; if it was meant in the application's time, it
  is corrected by entering it again. See "From 0.4.1 to 0.4.2" in
  [Install and operate](../install.md#upgrade).
- The web UI is not touched by the change to times: it sends every time with its zone.
- Going back to 0.4.1 needs no backup, since no schema changed: it is the one
  `apt install --allow-downgrades` command, and what was entered since is kept.
- The package test carries one `SKIP`: with no migration there is none to make fail, so
  that check is skipped and says so. The pass upgrades and goes back all the same.
- P-79 and P-80 are answered and are D-109 and D-110 in [Decisions](../decisions.md),
  the first changed by its answer. D-111 to D-113 are the grid, the reason and the
  examples.
- Scenarios S01 to S23 of the [build plan](../build-plan.md) pass.
