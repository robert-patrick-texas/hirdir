# hirdir 0.9.9

One fault of the web page mended, and nothing else: a list no longer gives way to the
page of a fault when its person comes back to the tab.

## Fixes

- **Coming back to the tab of a list leaves the list as it was** (P-264). With 0.9.8, a
  person who opened Items, Circuits, Catalog, External systems or Capacity, went to
  another tab of the browser for five seconds or more and came back, was shown "This
  page could not be drawn", with the text
  `TypeError: Cannot read properties of undefined (reading 'filter')`, where the list
  had been. It happened every time, to every person. With 0.9.6 and before, the same
  fault left the window blank; 0.9.7 gave it a page that says so and the text to copy,
  and that text, sent by the owner, is what led to the cause. The page reads its lists
  of choices again when its person comes back, so that a value added in another tab is
  offered; it took the lists it read for new ones though they held the same values,
  made the table again for them, and in doing so asked a question of the table it had
  just taken away. Now lists that are the same change nothing: the table keeps its
  rows, its place and what is ticked. And where a value did change meanwhile, the table
  is made again with it and no fault. Nothing was lost by the fault: Load again brought
  the list back each time.

## Additional Notes

- Upgrading from 0.9.8 changes nothing that is held: there is no migration, and the
  schema stays at revision `0014`. See "From 0.9.8 to 0.9.9" in
  [Install and operate](../install.md#from-098-to-099).
- A web page that was open while the upgrade ran is the page of 0.9.8 until it is
  loaded again, and has the fault until then. It says under its menu bar that a new
  version is installed, with a button, Load again.
- Going back to 0.9.8 needs no backup: it is the one `apt install --allow-downgrades`
  command.
- **The blank window of 0.9.7's notes is this fault.** It was not reproduced then,
  because the probe left a tab resting and never came back to one of these five lists
  with the server's own answers; the scenario that did come back to a tab answered it
  with something of another shape, and so took the fault it saw for one of its own
  making. Two browser scenarios now come back to each of the five lists with the
  server's own answers, once with the lists of choices as they were and once with a
  value edited meanwhile.
- The API is as it was in 0.9.8.
- What was to be 0.9.9, the server's own measures of its last minutes with a ceiling
  past which it answers at once to wait (P-262), and a process of its own for the work
  that no person waits for (P-263), is 0.9.10: the owner put this fix out by itself.
- The package test upgrades an installation of 0.9.8 with no migration, and carries one
  `SKIP`: with no migration there is none to make fail, so that check is skipped and
  says so. The pass upgrades and goes back all the same.
- Every component is at its latest production release. Nothing is held back. Since
  0.9.8, pydantic is at 2.14.4 with pydantic-core 2.50.5, and ruff at 0.17.6.
- Scenarios S01 to S35 and S39 to S53 pass.
